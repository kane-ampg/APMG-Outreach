Typecheck clean.

The research came back with the important finding up front: the multi-address change was **not** additive, it had two hard breaks. Both the server (`app/api/integrations/route.ts`) and the client (`NotifyEmailPanel`) validated with an anchored regex whose character classes exclude `@` — so a value with two `@` signs could never match, and a comma-separated list was rejected in both places. The client gate also disabled the Save button, meaning the operator physically could not save a list even before the server saw it. The two regexes were **inlined duplicates** of each other, which is exactly the drift risk that made a shared module the right fix.

`lib/pipeline/notifyEmails.ts` was written as that module: client-safe on purpose (with a comment forbidding putting it in `lib/pipeline/server.ts`, which reads the service-role key and must stay off the browser), accepting commas, semicolons (Outlook pastes) and newlines (spreadsheet columns) as separators, trimming, lowercasing, deduping, and joining to a canonical `"a@b.com, c@d.com"`. It rejects the whole list rather than silently dropping a bad or surplus entry, so a save can never quietly notify fewer people than the operator listed. The old server regex and its comment were deleted together — the comment claimed "same address shape the enquiry validator + n8n Gmail node accept", which would have invited someone to re-align the customer-facing enquiry validator to the list-aware one; that validator must stay strictly single-address as mailto header-injection defence, and it is still single-address today (`app/api/portal/inquiries/route.ts:60`).

The parser was then exercised directly rather than assumed: a throwaway ESM harness in the scratchpad ran 20 edge cases (blank, whitespace-only, duplicates differing in case, trailing commas, semicolon and newline separators, over-count, junk entries, over-paste). All 20 passed — but the run surfaced a real flaw the typechecker could never catch: `MAX_NOTIFY_RAW_LEN` was a hardcoded 2000, while ten maximum-length addresses is 10 × 254 = 2540 characters, so a legitimate full-size list would have been rejected by the raw cap before the count and per-address checks ever ran. The constant was rederived as `MAX_NOTIFY_EMAILS * (MAX_NOTIFY_EMAIL_LEN + 2)` = 2560 so it can only ever catch a genuine over-paste, and a second harness confirmed a 10 × 248-char list now parses while an 8,000-char paste is still refused.

On the UI side, re-seeding was tightened at the same time. The panel polls every 15s and previously did `setValue(initial)` unconditionally on every poll; clobbering a part-typed list of addresses is real data loss where clobbering one short address was survivable, so the effect now only re-seeds while the field still shows the last known saved value. Dirty-checking compares canonical-to-canonical, since saving normalises the text and a raw comparison would leave the field permanently dirty after every save; and after a successful save the field settles onto exactly what was stored, so the text matches the chips.

Verification was awkward. `npx next lint --file …` failed with "unknown option '--file'", and `npx eslint …` reported ESLint 10.8.0 could not find an `eslint.config.*` file — **the project has no ESLint config at all**, so lint is not an available gate here. The production build was used instead, which is the real gate: `npx tsc --noEmit` clean and `npx next build` compiled successfully, run twice (once after the copy/doc edits, again after the final save-settling polish). The reference workflow JSON was also re-parsed with Python to prove the sticky-note and code-node edits had not broken it (nodes: Sticky Note, Send Webhook, Format Enquiry, Send Notification, Respond OK). One minor friction point: extracting the research output through `python -c` hit a `cp1252` `UnicodeEncodeError` on an em-dash, so the reads were redone ASCII-safe.

The session closed by writing two memory files — one for the mailbox provisioning, one for the Gmail limits, since the limits research was expensive and generally reusable — and indexing both in `MEMORY.md`.

## Decisions
- **Credential link goes outside the repo, in a non-git folder.** Verified with `git rev-parse` rather than assumed. A Hudu shared URL in a tracked file is a leak waiting for the next `git push`.
- **Quote Evan's email verbatim in the log.** The provisioning facts (48-hour window, "available to login now") come from him; paraphrasing loses the source record and the date.
- **Same `app_settings` key, no migration.** The canonical single-address form is byte-identical to what the old code stored, so existing rows keep working. Consistent with the deliberate no-migration decision recorded in doc 18 for this same setting.
- **One shared parser module, client-safe.** The two inlined regexes were already duplicated; extracting one module is the only way the operator-visible validation and the enforced validation cannot drift. Explicitly *not* in `lib/pipeline/server.ts`, which touches the service-role key.
- **Reject the whole list, never partially accept.** Silently dropping a surplus or malformed entry would mean quietly notifying fewer people than the operator listed — a failure nobody would notice until an enquiry was missed.
- **Cap at 10, derived from nothing.** Not tuned to a transport ceiling: 10 is valid under Gmail API (500), SMTP (100) and smtp-relay (100 per transaction), and a Workspace admin can lower the real cap invisibly with a max-recipients compliance rule. Re-pointing the n8n node therefore cannot break the app. It is one exported constant if the user wants it higher.
- **One Gmail send addressed to all recipients, not a loop.** One message to N people = 1 message but N recipients against the daily caps; looping would multiply the message count and can lock the sending mailbox out for up to 24h.
- **All recipients on the `To:` line, stated in the UI copy rather than hidden.** Each recipient sees the others, which is correct for an internal ops list (reply-all context). Bcc would have required an n8n workflow edit and was out of scope — so the copy says it plainly.
- **Lowercase the entire address, not just the domain.** Makes case-differing duplicates collapse; Gmail (the only transport here) is case-insensitive on the local part too.
- **Derive `MAX_NOTIFY_RAW_LEN` from the other two caps.** A hardcoded floor can silently contradict the count and per-address checks; a derived one can only catch a genuine over-paste.
- **Production build as the gate, not lint.** There is no ESLint config in the project, so `tsc --noEmit` + `next build` is the honest verification story.

## Problems / gotchas
- **The multi-address change was a two-sided hard break, not an additive feature.** `EMAIL_RE` in `app/api/integrations/route.ts` and the inlined copy in `NotifyEmailPanel` were both anchored single-address regexes whose character classes exclude `@`, so *no* two-address value could ever validate — the Save button stayed disabled and the server would have returned 400 with "Enter a valid email address." The comma itself was allowed; the second `@` (and the whitespace ban, with `", "` separators) is what killed it. Found by the research pass **before** implementation, not by trial and error.
- **The old 200-char cap was quietly too small for a list** — at ~28 chars per address that is only ~6–7 addresses.
- **The parser's first raw-length cap was wrong in the safe-looking direction.** A fixed 2000 would have rejected a legitimate 10-address list of long addresses (2540 chars). Only the edge-case harness caught it; typecheck and build were both clean with the bug in place.
- **The panel's help text pointed the wrong way** after the move ("automation **above**" → "below"), and `lib/data/integrations.ts` pointed the wrong way *and* was singular. Copy that describes layout breaks silently when layout changes.
- **Polling could destroy part-typed input.** The pre-existing unconditional `setValue(initial)` on every 15s poll was tolerable for one short address and not tolerable for a ten-address list.
- **No ESLint config in the project.** `next lint --file` is not a valid invocation (unknown option) and `npx eslint` (v10.8.0) aborts for want of `eslint.config.js`. Lint is simply unavailable as a gate.
- **`python -c` printing the research output blew up** with a `cp1252` `UnicodeEncodeError` on an em-dash; re-run with `.encode('ascii','replace')`.
- **DNS propagating ≠ deliverability ready.** Called out explicitly at the time, because "the mailbox exists" reads like "we can send now". It was not, on that date.
- **The Hudu credential URL is in plaintext on disk.** Out of git, but not in a vault, and these links usually expire.
