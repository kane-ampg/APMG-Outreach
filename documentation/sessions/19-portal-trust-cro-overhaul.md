## Narrative

**The install.** The repo was fetched before touching anything: it declares a `.claude-plugin/marketplace.json` (`marketingskills`, v2.9.0, owner Corey Haines). `claude plugin marketplace add coreyhaines31/marketingskills` cloned over HTTPS (SSH not configured) and `claude plugin install marketing-skills@marketingskills` installed it at **user** scope, enabled. `claude plugin details` reported **48 skills**, no agents/hooks/MCP servers. The one caveat flagged to the user: the always-on skill descriptions add roughly **12.5k tokens to every session**, disable-able with `claude plugin disable marketing-skills`.

**The dead end that shaped the audit.** A plugin's skills don't appear in the available-skills list until the session restarts, so `/cro` could not actually be invoked. Rather than ask the user to restart, the skill files were located under `~/.claude/plugins/marketplaces/marketingskills/skills/` and `cro/SKILL.md` + `marketing-psychology/SKILL.md` were read and followed directly.

**The critique.** No browser was driven; the portal surfaces were read as code — `ServicesPortal.tsx`, `ServiceInquiryModal.tsx`, `PortalConsentGate.tsx`, `PortalChat.tsx`, `TeamSection.tsx`, `Footer.tsx` — plus `Company-Brief.md` and `components/knowledgebase/business.md` for what APMG can actually *claim*. (`middleware.ts` — what the customer host is even allowed to serve — was read at the start of the *next* turn, as the first step of the fix pass, not as part of the critique.) The framing that drove everything: this is a **post-click landing page for cold, sector-targeted outreach**, i.e. the highest-suspicion traffic there is. The visitor didn't ask for the email and is deciding in seconds whether this is a real Melbourne trades business or an AI-generated spam funnel.

Two findings led. **(1) There was no phone number anywhere on the page** — not the hero, not the "Where to find us" card (address + website only), not the footer, not the chat. For property maintenance, where half the demand is "the ceiling is leaking, who can come now", that reads as a lead-capture farm. **(2) The first thing a cold visitor saw was a legal wall** — `PortalConsentGate` blocked the entire page on arrival with "Before you continue — please review our Terms & Conditions and Privacy Policy", before any value had been shown, which is the exact shape of a credential-phishing page. The same finding noted that the gate re-prompts on *every* fresh visit — `PortalConsentGate` stores the acknowledged version in `sessionStorage` (`apmg-legal-ack-version`), deliberately, so a new tab or browser re-triggers the wall. *(The condensed transcript truncates the remainder of the findings list after this point — ~11k characters are elided — so the full worst-first ordering beyond these two is not recoverable from the record; what was implemented in the next turn is, and is listed below.)*

**"Lets fix everything."** The implementation ran in dependency order. `lib/legal/company.ts` first, since everything references it: `phone: "1300 97 97 40"` and `phoneHref: "tel:1300979740"`, with a comment recording that the KB's "1300 97 97 40" and "1300 979 740" are the same digits. Then `app/api/portal/context/route.ts` (sector hint, `sameOrigin`-gated, `private, no-store`), then `LegalDocPage.tsx` + the two `/portal/*` pages (nested under `app/portal` so the existing host-wall `PORTAL_ALLOW` prefix already permits them and the portal layout's light-theme bootstrap applies), then the gate removal, then the footer, then the chat, then `TeamSection`, then the long `ServicesPortal` pass, then the enquiry modal.

Small snags along the way: the `Footer.tsx` rewrite was attempted with `Write` before the file had been read in-session and was refused, so it was read then written. A stray CJK character slipped into a new comment (`"top客 pain point"`) and needed a repair edit. Photo treatment was flipped from `object-contain` to `object-cover` in three places (card banners, hero layers, modal photo panel) on the reasoning that matte letterbox bars read as placeholder content on a trust page. `npx tsc --noEmit` and `npm run build` were both clean.

The session then wrote a project memory (`portal-trust-rules.md`) and appended its index line to `MEMORY.md`.

**WhatsApp.** The user redirected the hero's number button to WhatsApp. `whatsappHref: "https://wa.me/611300979740"` went into `company.ts` with an explicit warning comment that this assumes a WhatsApp Business account is registered against the 1300 number — 1300 numbers often cannot hold one. lucide ships no brand icons, so `WhatsAppIcon.tsx` carries the official glyph as an inline SVG (path from simple-icons), `currentColor`, className passthrough. The button was restyled in WhatsApp green `#25D366` — called out in the code as the one sanctioned non-token hue, because instant brand recognition *is* the point — and tracked as `portal_whatsapp_click`. `tel:` calling stayed on the contact card and footer so callers aren't stranded.

**Google Reviews, take one.** The user pasted their Google listing URL. The Chrome session junk (`gs_lcrp`, `sourceid`, `oq`, …) was stripped and only the `#lrd=0x6ad6319e6f7bafcf:0xca054939c7c38206,1,,,,` fragment — the bit that opens the reviews overlay — was kept, stored as `COMPANY.googleReviewsUrl`. A `GoogleIcon.tsx` (four-colour "G", same rationale as the WhatsApp glyph) was added, `PORTAL_TABS` gained a `reviews` pill between Services and Team, the hero got matching copy and reused the depot photo for the new layer, and an inline `ReviewsPanel` rendered a confident hand-off card whose argument was that the proof deliberately lives somewhere APMG can't edit it.

**"is there a way we can I frame this?" — take two.** Answer: no. `google.com/search` and the reviews overlay send `X-Frame-Options` / `frame-ancestors`, so the browser itself refuses; every "embedded Google reviews" widget is really a Places API fetch rendering its own HTML. So that was built: `app/api/portal/reviews/route.ts` (server-side Places fetch, key never reaching the browser, 6-hour cache ≈ 4 calls/day, last-good-result retention so a quota blip can't blank the tab) plus a live `GoogleReviewsPanel` that fell back to the hand-off card until `GOOGLE_PLACES_API_KEY` existed. It typechecked and built.

**"never mind lets not go that path" — take three.** The user declined the API key and pasted the review text instead. `app/api/portal/reviews` was deleted (`rm -rf`), `public/reviews/` was created with a README explaining the photo-drop convention, and the reviews became data: `components/apmg/googleReviews.ts`, documented as a **snapshot, not live**, with a verbatim-only rule, a `truncated` flag for the six reviews whose Google snippet ended in "… More" (rendered as an ellipsis + "Read the full review on Google" rather than pretending to have the text), owner replies included because they directly counter the "poor follow-up after quoting" objection, and an optional `photos` array. `GoogleReviewsPanel` was rewritten to render it: rating header, paginated grid (6 per page, prev/next chevrons + numbered pills, direction-aware slide, `scrollIntoView` back to the grid top, reduced-motion aware), and a "Leave us a review" line.

Deleting the route left a stale generated type behind — `.next/types/validator.ts(242,39): error TS2307: Cannot find module '../../app/api/portal/reviews/route.js'`. The production build regenerated it and a re-run of `tsc --noEmit` was clean.

The session closed with two honest caveats the user was told outright: the job photos could not be extracted out of the pasted screenshots into files (the strip renders the moment files land in `public/reviews/` and get listed), and two reviews sit slightly awkwardly with the brand rules — Carmel Spano's "half the price that others quoted" against the rule about not competing on cheapness, and Meekee Dee's being four years old. A reorder was offered, not applied.

## Decisions
- **Follow the skill files by hand rather than restart the session.** A fresh plugin's skills aren't in the available-skills list until restart; reading `cro/SKILL.md` and `marketing-psychology/SKILL.md` off disk got the same guidance without losing the session's context.
- **Fact-only copy is the governing rule.** "Trusted" is for the visitor to conclude; "family-run since 2015" is for APMG to say. Every `PROOF_POINTS` line must be substantiated in `components/knowledgebase/business.md`, and the highest-value additions (insurance amount, licence numbers, police-check/WWCC policy, ABN) are left as an explicit `TODO(trust)` to be added *the day the certificate is in hand*.
- **Remove the entry gate, keep the enquiry gate.** Consent is captured where PII is actually collected — server-authoritative and fail-closed, unchanged from session 18. `PortalConsentGate.tsx` stays in the repo, unmounted, in case a contract ever requires an acknowledge-to-view wall.
- **Policies as pages, not just modal text.** `/portal/terms` and `/portal/privacy` render the same `loadLegalDocs()` source the consent pins, so a procurement officer can bookmark or forward them and the linked text can never drift from the consented text.
- **Never print "TBC" to a customer.** The customer footer omits the ABN segment entirely while `COMPANY.abn` is `null`, and slots it in automatically once set. (The session-18 `abnLine()` helper, which *does* render an explicit `"ABN: TBC"` marker, was left untouched — but note it is a dead export: nothing in the repo has ever called it, so no surface actually shows that marker. `senderIdentityLine()`, used by the unsubscribe email, applies the same omit-while-null rule as the footer.)
- **Pull the "Developed by APMG AI Team" credit off the customer host only.** It was client-requested, so it was flagged to the user as a one-line revert rather than silently deleted.
- **Reviews stay on Google.** The trust argument *is* that the proof lives somewhere APMG can't edit — hence the link-out framing ("hosted where we can't edit a word of them") and the refusal to paraphrase, "improve" or invent review text.
- **Snapshot over API, at the user's choice.** The Places integration was working and building; the user preferred hard-coded and free. The file therefore carries an explicit "SNAPSHOT, not live" header and a manual update procedure.
- **Truncated reviews stay truncated.** Where the pasted snippet ended in "… More", the card shows an ellipsis + a link to the source instead of fabricating the remainder.
- **`object-cover` over `object-contain`.** Matte/letterbox bars around a job-site photo read as placeholder content on the page a cold visitor is judging for legitimacy.
