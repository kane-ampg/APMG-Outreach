## Objective
One line from the user: *"each Page I go the title of the page should change like that please"* — the browser tab should name the surface you're actually looking at, instead of every screen in the app sharing the single static root title (`APMG — Lead Gen`). No further requirements were given; the framing ("like that") appears to reference something the user was pointing at on screen, which the transcript does not capture, so the interpretation — browser **tab/document title** per surface — was the assistant's read of it and was never confirmed: the session ends on the assistant's summary with no reply from the user.

## TL;DR
- **Diagnosed the real constraint first:** the whole internal console is a *single* Next.js route (`app/page.tsx` → `DashboardShell`) with client-side tab state, so Next's static `export const metadata` cannot express a per-tab title. At the time only two files in `app/` exported metadata at all — the root layout and `app/portal/page.tsx`.
- **Added a title helper to the existing nav config** (`lib/nav.ts`): `APP_NAME = "APMG Lead Gen"` plus `tabTitle(tab)` returning `` `${TAB_LABEL[tab]} — ${APP_NAME}` `` — deliberately built on the existing `TAB_LABEL` map so page names stay defined in exactly one place.
- **Wired it imperatively into the shell** (`components/apmg/DashboardShell.tsx`): a `useEffect` on `activeTab` sets `document.title = tabTitle(activeTab)`. The tab now reads "Overview — APMG Lead Gen", "Sales — APMG Lead Gen", "Telemetry — APMG Lead Gen", etc.
- **Gave the sign-in page a real title** via a new 15-line `app/login/layout.tsx` — `app/login/page.tsx` is `"use client"`, so it cannot export `metadata` itself; the thin pass-through layout exists purely to set `Sign in — APMG Lead Gen`.
- **Page name leads, brand trails** — so the useful half survives the truncation a narrow browser tab applies to the end of the string.
- **Deliberately left `/portal` alone.** It already sets `Our Services — APMG Services` — the *customer* brand — and suffixing it with the internal "Lead Gen" naming would leak operator vocabulary to prospects.
- **`tsc --noEmit` failed, but not on the new code:** stale generated route types in `.next` didn't know about the new `/login` layout (`TS2344: Type 'Route' does not satisfy the constraint 'LayoutRoutes'`). `npm run build` regenerated them and came out clean.

## Decisions
- **Imperative `document.title` in the shell, not per-route `metadata`.** Follows from the architecture: the console is a single route. Splitting the console into real routes to get declarative metadata would have been a large, risky refactor for a cosmetic win — explicitly not attempted, and the reason is recorded in a code comment at the effect.
- **Derive titles from `TAB_LABEL` rather than a new title map.** `TAB_LABEL` is already the shared human-name source for the command bar and the "not wired up yet" placeholder; a parallel map would guarantee eventual drift.
- **Page name first, brand suffix second** (`"Overview — APMG Lead Gen"`). Browser tabs truncate the *end* of the string, so the identifying half must lead. Documented in the `tabTitle` docblock.
- **A layout file, not a server-component conversion, for `/login`.** Cheapest way to give a client page a title; costs 15 lines and touches nothing about the sign-in behaviour.
- **`/portal` deliberately excluded.** It keeps `Our Services — APMG Services`: it's the customer trust surface, and the internal "Lead Gen" naming has no business appearing in a prospect's browser tab. (This is consistent with `app/portal/terms/page.tsx` and `app/portal/privacy/page.tsx`, which use `Terms & Conditions — APMG Services` / `Privacy Policy — APMG Services` — but note those were written *after* this session, ~5 minutes later at 07:52 local, by [session 19](19-portal-trust-cro-overhaul.md), and are not its work despite riding in the same commit `08f162a`.)
- **Root layout title left as `APMG — Lead Gen`.** It stays the pre-hydration default for `/` — the imperative title only lands once the client effect runs.

## Problems / gotchas
- **`tsc --noEmit` was a false alarm.** The `TS2344 … 'LayoutRoutes'` error came from stale generated route types under `.next/` that predated the new `/login` layout, not from the new code. Diagnosed correctly and cleared by `npm run build`. Worth remembering: **adding a route file invalidates `.next` route typings, so type-check via a build (or after a dev-server restart) rather than trusting a bare `tsc` run.**
- **Titles are hydration-dependent.** `document.title` is set in a client effect, so the first paint of `/` shows the root layout's `APMG — Lead Gen` before switching to the active surface's title. Acceptable for an authenticated internal console; it is not a server-rendered title and would not be what a crawler or a link-preview scraper sees.
- **Sub-tabs don't get their own titles.** Pipeline has internal sub-navigation (`PipelinePage` holds its own `sub` state — "Leads" vs. "Send Campaigns (Automation)"), and the document title only reflects the top-level `TabId`, so both read "Pipeline — APMG Lead Gen". Same for any other in-page tab state. Not raised in the session; recorded here as a known limit.
- **No URL changes, so no deep links or history.** Navigating tabs updates the title but not the address bar; you can't bookmark or share "the Telemetry page", and back/forward don't move between surfaces. The title is now the only per-surface identity signal in the browser chrome. Out of scope for the request, but it's the obvious next ask.
- **The user's "like that" reference is unrecoverable from the transcript, and the request was never confirmed.** The record holds exactly one user turn, captured as plain text with no attachment noted (a condensed transcript can't fully rule out a screenshot in the original), and the session ends on the assistant's summary — no reply. So "browser tab/document title" remains the assistant's reading. If the user was pointing at something else (an in-page heading, per-route URLs, a breadcrumb), the record does not say so and nothing in this session tested the interpretation against them.
